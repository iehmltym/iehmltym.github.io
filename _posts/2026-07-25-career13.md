# 1.1 什么是互联网（Internet）

互联网（Internet）不是一个软件，而是**全世界大量网络互相连接形成的巨大网络**。

例如：

```text
你的电脑
    │
家庭路由器
    │
运营商
    │
Internet
    │
Google服务器
```

互联网最大的目的只有一个：

> **让两台计算机能够通信。**

但是通信需要解决很多问题。

例如：

* 我不知道对方是谁。
* 我不知道对方在哪里。
* 我不知道怎么把数据送过去。
* 我不知道有没有丢包。
* 我不知道别人会不会偷看。

于是，一项项技术就诞生了。

---

# 1.2 TCP/IP 模型（★★★★★）

SG 不要求你背 OSI 七层，但一定要理解 TCP/IP。

```
应用层（Application）
│
├── HTTP
├── HTTPS
├── SMTP
├── FTP
├── DNS
└── POP3 / IMAP

传输层（Transport）
│
├── TCP
└── UDP

网络层（Internet）
│
└── IP

网络接口层（Link）
│
└── MAC
```

记住一句话：

> **上层使用下层提供的服务。**

例如：

HTTP 不会自己发送数据。

它必须：

```
HTTP
 ↓
TCP
 ↓
IP
 ↓
MAC
 ↓
网线
```

---

# 1.3 IP —— 找到目标计算机（★★★★★）

IP（Internet Protocol Address）就是：

> **网络中的地址。**

例如：

```
8.8.8.8

192.168.1.10

10.0.0.5
```

每台联网设备至少有一个 IP。

作用：

> **告诉数据应该送到哪台计算机。**

例如：

```
你的电脑

↓

203.0.113.5（服务器）
```

如果没有 IP：

数据根本不知道去哪。

---

# 1.4 MAC —— 找到目标网卡（★★★★★）

很多人容易把 IP 和 MAC 混。

实际上：

IP：

> 找电脑。

MAC：

> 找网卡。

例如：

```
Internet

↓

公司网络

↓

某一台电脑

↓

网卡
```

MAC 地址：

```
00-1A-2B-3C-4D-5E
```

每块网卡出厂就有。

考试记一句：

> **IP 是逻辑地址；MAC 是物理地址。**

---

# 1.5 为什么需要 ARP？（★★★★★）

现在：

已经知道：

```
IP：

192.168.1.20
```

但是：

不知道：

```
MAC：

？？？
```

怎么办？

ARP（Address Resolution Protocol）负责：

> **根据 IP 查询 MAC。**

流程：

```
知道 IP
    │
ARP 广播：
"谁是 192.168.1.20？"
    │
目标主机回复：
"我是，我的 MAC 是 xx-xx-xx"
    │
获得 MAC
    │
开始发送数据
```

考试一句话：

> **ARP = IP → MAC。**

---

# 1.6 DNS —— 为什么不用背 IP？（★★★★★）

如果没有 DNS。

你访问 Google：

必须输入：

```
142.250.xxx.xxx
```

根本记不住。

于是：

DNS（Domain Name System）出现。

作用：

> **把域名转换成 IP。**

例如：

```
www.google.com

↓

142.250.xxx.xxx
```

所以：

浏览器真正访问的是：

IP。

不是：

域名。

---

# 1.7 TCP —— 保证可靠通信（★★★★★）

IP：

只负责：

> 尽力送。

它不保证：

* 一定送到
* 顺序正确
* 不重复
* 不丢失

于是：

TCP 出现。

TCP 保证：

* 数据可靠到达
* 按顺序到达
* 丢包重传
* 流量控制
* 拥塞控制

所以：

HTTP、HTTPS、SMTP、FTP 都建立在 TCP 上。

---

# 1.8 UDP —— 更快，但不保证可靠（★★★★★）

UDP：

什么都不保证。

特点：

* 不建立连接
* 不重传
* 不排序
* 延迟低
* 速度快

适合：

* 视频直播
* 在线游戏
* VoIP
* DNS 查询

考试：

TCP = 可靠。

UDP = 快。

---

# 1.9 Port（端口）

IP：

找到电脑。

Port：

找到程序。

例如：

```
192.168.1.10

↓

Chrome（80）

Outlook（25）

SSH（22）
```

服务器通过：

```
IP + Port
```

确定：

到底给哪个程序。

| ----- | --- | ---- |

# 1.11 浏览器访问网页全过程（★★★★★）

假设输入：

```
https://www.google.com
```

实际上发生：

```
① 输入域名

↓

② DNS 查询

↓

得到 IP → ARP → MAC

↓

⑦ 发送 HTTP 请求

↓

⑧ 服务器响应

↓

⑨ 浏览器渲染页面
```

**这张流程图是整本书最重要的一张图。**

后面所有内容都会挂在这里：

* DNS
* TCP
* TLS
* CA
* 数字证书
* AES
* HTTP

都是在这九步里的不同位置。

# 2.1 为什么 HTTP 会出现？

互联网刚诞生的时候，人们只想完成一件事情：

> **让浏览器能够向服务器获取网页。**

于是出现了：

HTTP（HyperText Transfer Protocol）

即：

> **超文本传输协议**

HTTP 本身非常简单。

浏览器：

```text
GET /index.html
```

服务器：

```text
HTTP/1.1 200 OK

<html>......</html>
```

整个过程：

```text
浏览器
    │
HTTP Request
    │
服务器
    │
HTTP Response
    │
浏览器
```

HTTP 只负责：

> 请求（Request）
>
> 响应（Response）

---

# 2.2 HTTP 为什么不安全？

HTTP 最大的问题：

**明文传输（Plain Text）**

例如：

登录：

```text
用户名：admin

密码：123456
```

HTTP：

直接发送：

```text
admin

123456
```

如果有人监听网络：

```text
浏览器

↓

Internet

↓

服务器
```

中间：

```text
黑客
```

他就能直接看到：

```text
账号

密码

聊天内容

银行卡号
```

这就是：

**窃听（Eavesdropping）**

---

## HTTP 三大问题

### ① 数据泄露（Confidentiality）

任何人都能看到。

例如：

```text
密码

聊天内容

订单信息
```

全部都是明文。

---

### ② 数据被修改（Integrity）

例如：

服务器：

本来发送：

```text
价格：

100元
```

中间人：

偷偷改成：

```text
10000元
```

浏览器：

完全不知道。

---

### ③ 身份无法确认（Authentication）

例如：

你输入：

```text
www.bank.com
```

浏览器：

怎么知道：

现在连接的是：

真正银行？

还是：

黑客服务器？

不知道。

所以：

HTTP：

存在三个问题：

```text
不能保密

不能保证完整

不能证明身份
```

---

# 2.3 HTTPS 为什么诞生？

于是：

HTTPS 出现。

很多人以为：

HTTPS 是：

新的协议。

其实不是。

真正关系：

```text
HTTPS

↓

HTTP

+

TLS（SSL）
```

所以：

HTTPS：

其实就是：

> **HTTP + TLS 加密**

HTTP：

负责网页。

TLS：

负责安全。

---

# 2.4 SSL 与 TLS

考试里面：

SSL

TLS

几乎混着说。

实际上：

SSL 是早期版本。

后来：

升级：

变成：

TLS。

今天：

真正使用：

TLS。

但是：

大家仍然习惯说：

SSL证书

SSL连接

SSL加密。

考试：

看到：

SSL

TLS

可以认为：

基本一样。

---

# 2.5 TLS 到底解决什么？

TLS：

一次解决：

HTTP 三个问题。

---

## ① 保密（Confidentiality）

别人：

看不到内容。

例如：

原来：

```text
密码：

123456
```

现在：

变成：

```text
8A F2 6B 13 XX...
```

别人：

看不懂。

---

## ② 完整性（Integrity）

TLS：

会验证：

数据：

有没有被修改。

如果：

黑客：

改：

```text
100

↓

10000
```

浏览器：

立即发现。

连接失败。

---

## ③ 身份认证（Authentication）

浏览器：

必须确认：

现在连接的是：

真正：

Google。

不是：

假的。

于是：

数字证书：

诞生。

---

# 2.6 什么是数字证书（★★★★★）

数字证书：

可以理解成：

> 网站身份证。

例如：

Google：

拥有：

```text
Google 身份证
```

浏览器：

连接：

Google。

第一件事情：

不是：

发送账号。

而是：

先说：

```text
把身份证拿出来。
```

Google：

发送：

数字证书。

浏览器：

检查：

```text
是不是Google？

是不是过期？

是不是假的？

是不是可信机构签发？
```

全部通过。

才继续。

---

# 2.7 数字证书里面有什么？

考试重点：

数字证书：

主要包含：

```text
域名

公钥

签发机构（CA）

有效期

数字签名
```

注意：

考试喜欢考：

> 证书绑定什么？

答案：

**域名（Domain）**

不是：

IP 地址。

所以：

服务器：

今天：

```text
1.1.1.1
```

明天：

```text
2.2.2.2
```

只要：

DNS：

解析正确。

证书：

不用重新申请。

---

# 2.8 CA 是什么？

问题来了。

Google：

自己说：

```text
我是Google。
```

可信吗？

当然：

不可信。

于是：

需要：

第三方。

这个第三方：

就是：

CA（Certificate Authority）

即：

> 数字证书认证机构。

例如：

```text
Google

↓

申请证书

↓

CA审核

↓

CA签名

↓

浏览器信任
```

所以：

浏览器：

真正相信的是：

CA。

不是：

Google 自己。

---

# 2.9 Root CA

浏览器：

为什么相信：

CA？

因为：

浏览器：

出厂：

已经内置：

很多：

Root CA。

例如：

```text
Chrome

↓

Root CA列表

↓

DigiCert

GlobalSign

Let's Encrypt

……
```

浏览器：

收到证书。

第一件事情：

检查：

```text
是不是这些Root CA

签发的。
```

如果：

不是。

浏览器：

立即：

弹出：

```text
你的连接不是私密连接。
```

考试：

最喜欢考：

> 浏览器为什么信任服务器？

答案：

> **因为信任 Root CA。**

---

# 2.10 RSA 为什么出现？

现在：

浏览器：

已经知道：

是真Google。

但是：

还有问题。

AES：

需要：

双方：

拥有：

同一个密钥。

问题：

这个密钥：

怎么发送？

如果：

直接发送：

```text
AES Key
```

黑客：

一样能看到。

于是：

RSA：

出现。

RSA：

负责：

**安全交换 AES 密钥。**

注意：

RSA：

不是：

负责整个网页加密。

考试：

最容易混这里。

---

# 2.11 为什么不用 RSA 加密整个网页？

因为：

RSA：

太慢。

AES：

非常快。

所以：

HTTPS：

真正流程：

```text
RSA

↓

交换AES密钥

↓

AES

↓

加密网页
```

考试：

一句话：

> RSA 负责密钥交换。

> AES 负责真正加密数据。

# 2.12 HTTPS 完整流程（★★★★★）

输入：

```text

```

证书。

# 第三章 TCP、UDP —— 为什么有的网络很可靠，有的网络很快（★★★★★）

> 学完本章，你应该能够回答：
>
> - TCP 和 UDP 到底有什么区别？
> - 为什么 HTTP 一定使用 TCP？
> - 为什么直播、游戏大量使用 UDP？
> - TCP 三次握手为什么存在？
> - 为什么会有四次挥手？
> - 为什么会出现 TIME_WAIT？
> - SG 考试关于 TCP/UDP 的题基本都能做出来。

---

# 3.1 为什么需要 TCP？

上一章我们知道：

IP 可以负责：

> 把数据送到目标计算机。

但是：

IP 并不保证：

```text
一定送到

不会重复

不会丢失

顺序正确
```

例如：

发送：

```text
A

B

C
```

网络可能变成：

```text
A

C

B
```

甚至：

```text
A

C
```

B 丢了。

IP 根本不管。

所以：

必须有人负责：

> "保证数据可靠。"

于是：

TCP（Transmission Control Protocol）

出现。

---

# 3.2 TCP 的作用

TCP 可以理解成：

> **可靠运输公司。**

它负责：

```text
建立连接

保证送达

保证顺序

发现丢包

重新发送

控制速度

避免网络堵塞
```

一句话：

> TCP = Reliable（可靠）

---

# 3.3 UDP 为什么还存在？

很多人第一次学习都会问：

既然 TCP 那么厉害，

为什么还要 UDP？

答案：

因为：

TCP 太慢。

例如：

视频聊天：

如果：

一句话：

```text
你好
```

丢了。

TCP：

```text
重新发送

等待

确认

继续
```

画面：

开始卡。

但是：

视频：

真正需要的是：

流畅。

丢一帧：

根本没人发现。

于是：

UDP：

出现。

---

# 3.4 UDP 的特点

UDP：

什么都不保证。

它只有一句话：

> **我负责发送，收到没有我不管。**

特点：

```text
无连接

没有确认

没有重传

没有排序

速度快

延迟低
```

所以：

UDP：

经常用于：

```text
视频

直播

语音

在线游戏

DNS
```

---

# 3.5 TCP VS UDP（★★★★★）

| TCP | UDP |
|------|------|
| 建立连接 | 不建立连接 |
| 有确认 | 无确认 |
| 保证送达 | 不保证 |
| 有重传 | 无重传 |
| 有顺序 | 无顺序 |
| 较慢 | 很快 |
| 可靠 | 高效率 |

考试：

最喜欢：

问：

哪个：

适合：

视频？

答案：

UDP。

哪个：

适合：

银行转账？

答案：
