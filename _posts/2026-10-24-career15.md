# 基本情報技術者試験（FE）科目B 勉強ノート


## 基本情报技术者考试・科目B：全书变量名与函数名读题笔记

读题时，先看函数名猜它要做什么，再看变量第一次被赋值的地方，确认它装的是**位置、数据，还是节点引用**。

这里收录程序里的变量、参数、数组、类、函数、方法，以及读题需要的数学和图示符号。带框的 `【a】`、`【b】` 是填空编号；如果程序真的声明了 `a`、`b`，才按变量解释。单字母没有固定含义，换一道题就要重新确认。

## 第1章：算法与数据结构

| 小节 | 名字 | 原意与读题方式 |
|---|---|---|
| 1.1 算法的表示 | 流程图、伪代码 | 流程图就沿箭头读：「现在做什么？做完下一步去哪？」伪代码则从第一行开始，遇到条件再选要执行的分支。 |
| 1.2.1～1.2.4 变量、声明、赋值 | `a`、`b`、`c`、`moji`、`str` | `a/b/c` 是示例里给格子起的名字。`moji` 来自日语「文字」，可以装一个字符 `"A"`；`str` 来自 *string*，可以装一整串字符。`a ← b` 就是先读 `b` 里的值，再写进 `a`。 |
| 1.2.5 交换变量 | `a`、`b`、`TMP`、`W` | `TMP` 来自 *temporary*，临时保管；`W` 在示例里也做这个工作。把 `a` 想成一个马上要被覆盖的格子，先用临时变量存住它的旧值，之后才能把旧值交给 `b`。 |
| 1.3.1～1.3.2 一维数组 | `TBL_A`、`TBL_B`、`TBL_C`、`n` | `TBL` 来自 *table*，就是一排有编号的格子，后缀区分不同示例。`n` 用来表示元素个数时，读成「一共有几格」。`TBL_A[3]` 是第3格**里面的东西**。 |
| 1.3.3 二维数组 | `TBL_D`、`A`、`i`、`j`、`m`、`n` | 二维数组像座位表：`A[i,j]` 是第 `i` 行、第 `j` 列的格子。`m/n` 描述尺寸时，要看题目分别用哪个数行、哪个数列。 |
| 1.3.4 数组的数组 | `TBL_E` | 外面是一排盒子，每个盒子里又是一排格子。看到两层下标，先找外面的盒子，再找盒子里的那一格。 |
| 1.4.1 链表 | 节点、引用 | 节点像一张卡片，卡片上既有数据，也写着下一张卡片的位置。顺着这些位置走，就能读出链表顺序。 |
| 1.4.2 数组实现链表 | `Value`、`Next`、`First`、`Prev` | `Value[i]` 问「第 i 张卡片上写什么」，`Next[i]` 问「下一张去哪格找」，`First` 问「从哪格出发」，`Prev[i]` 问「上一张在哪格」。书里的这个示例用 `−1` 表示到尾，用 `0` 表示没接进链表。 |
| 1.4.2 第30页 | `box`、`next` | `box[i]` 装数据，`next[i]` 装下一站的**编号**。例如 `box[1] = A`、`next[1] = 5`，就是「A 后面去5号格」。本题 `next[0]` 存入口，节点的 `next` 为 `0` 表示走完。 |
| 1.5.1 栈 | `stack`、`top`、`push`、`pop` | 像叠盘子：`push` 把盘子放上去，`pop` 拿走最上面一个。`top` 用来定位栈顶附近的操作位置；到底指着已有的顶格还是下一个空格，要对照这题的代码。 |
| 1.5.2 队列 | `queue`、`x`、`y` | `queue` 像排队；`x/y` 是排进去的数据。先进去的先出来。 |
| 1.5.3 循环队列 | `First`、`End`、`N`、`mod` | `First/End` 追踪队列两端，`N` 是环形数组容量。`mod` 是取余：走到末端再走一步，就绕回开头。哪一端指已用格、哪一端指空格，看本题约定。 |
| 1.6.1～1.6.2 树与遍历 | 根、父节点、子节点、叶节点、图中 `a/b/c/d` | 圆圈里的字母只是节点名字。前序、中序、后序问的是：「看当前这个圆圈的时机，是在走孩子之前、两个孩子之间，还是之后？」 |
| 1.6.3 二叉搜索树 | 左子树、右子树 | 例如找14，眼前是13，就往右；眼前是15，就往左。比较的是圆圈里的**值**。 |
| 1.6.4 数组实现树 | `tree`、`value`、`parent`、`left`、`right` | `tree` 是存树的表。`value` 是节点里装的值；`parent/left/right` 是路线：父节点、左孩子、右孩子在哪。 |

## 第2章：伪代码和面向对象

| 小节 | 名字 | 原意与读题方式 |
|---|---|---|
| 2.1.1 过程 | `prog`、`sub`、`m`、`n` | `prog` 来自 *program*，示例主过程；`sub` 来自 *subroutine*，被叫来办事的子过程。`sub(3,5)` 就是把3、5交给这次调用的 `m/n`。 |
| 2.1.2 函数 | `func`、`m`、`n` | `func` 来自 *function*，名字只说「这是个函数」。它要算什么，得看收进来的 `m/n` 和最后 `return` 的内容。 |
| 2.1.3 全局和局部 | 全局 `m/n`、局部 `m/n` | 先找声明的位置。局部参数像每次调用自己的工作纸；全局变量像大家共用的一张纸。`proc(n−1)` 会把算好的值交给新调用，外面那层的 `n` 不会因此被改掉。 |
| 2.2 条件和运算符 | `a`、`b`、`mod` | `a/b` 是拿来判断或计算的示例值。`mod` 是取余，例如 `5 mod 2 = 1`，意思是5除以2还剩1。 |
| 2.3 分支 | `a`、`x`、`kingaku`、`point` | `a` 是示例里被判断的值，`x` 是分支里要写的值。`kingaku` 来自日语「金額」，`point` 是积分。可以先把程序读成：「看金额在哪一档，按这一档算积分。」 |
| 2.4.2 `while` | `sum`、`a`、`i`、`TBL`、`n`、`x` | `sum ← sum + a` 是把这次的 `a` 加到以前的总和；`TBL[i]` 是用 `i` 查表。看到 `n/x` 先找初值，再看每轮是增加、减少，还是被替换。 |
| 2.4.3 `do-while`、二分查找 | `binarysearch`、`T`、`data`、`low`、`high`、`mid` | `T` 是要翻的表，**这题的 `data` 是要找的数字**。`low/high` 是夹住搜索范围的两根手指，`mid` 是中间格号，`T[mid]` 才是拿来比较的值。 |
| 2.5.1 `for` | `i` | 每轮看 `i` 变成了多少。如果它出现在 `TBL[i]`，就表示这次轮到第 `i` 格。 |
| 2.5.2 一维数组 | `TBL`、`sum`、`i` | `i` 从头扫到尾，`TBL[i]` 是这次拿出来的数，`sum` 记录一路加出的结果。 |
| 2.5.3 二维数组 | `MTBL`、`i`、`j`、`sum`、`min` | `MTBL[i,j]` 先定位行，再定位列。`sum` 是已经加了多少；`min` 是目前看过的数里，最小的那个。 |
| 2.6.1 栈类 | `Stack`、`stack`、`top`、`push(x)`、`pop()`、`num`、`st/st1/st2` | `Stack` 是做栈的模板，`stack` 是某个栈内部的存储数组。`push(x)` 的 `x` 是要放进去的值，构造函数示例里的 `num` 指定大小；`st/st1/st2` 指向各自的栈实例。 |
| 2.6.2 链表类 | `List`、`value`、`val`、`next`、`first`、`new`、`follow`、`pre` | `List` 是节点类；`val` 是建节点时交进去的值，`value` 是节点实际存的值。`first` 指入口，`new` 指新节点，`follow` 是顺着链往后走的手指，`pre` 记前一节点。 |
| 2.6.3 二叉搜索树类 | `Tree`、`value`、`left`、`right`、`lookup`、`t`、`data` | `Tree` 是类，`lookup` 是查找。`t` 指现在站的节点，`data` 是要找的数。比较 `data` 和 `t.value` 后，沿 `t.left` 或 `t.right` 往下走。 |

## 第3章：基础例题

| 题号 | 名字 | 原意与读题方式 |
|---|---|---|
| 3.1 评定成绩 | `gradeEvaluation`、`inData`、`eResult` | `gradeEvaluation` 是评定成绩。`inData` 是交进来的分数，`eResult` 是选出的评语，例如 `"A"`。先问分数落在哪一档。 |
| 3.2 求整数之和 | `sum`、`num`、`x`、`i` | `sum(num)` 问「从1加到 `num` 等于多少」。`i` 是这次要加的数，`x` 是加到目前为止的总数。 |
| 3.3 求数组中的数值 | `func`、`data`、`n`、`a`、`i` | `func` 是泛用名。`n` 告诉你 `data` 有几格；`i` 指现在看到第几格；`a` 记目前的候选值。要知道它最后找出什么，就看什么条件会把 `data[i]` 写进 `a`。 |
| 3.4 连接数组 | `conCat`、`x`、`y`、`z`、`len_x`、`len_y`、`k` | `conCat` 来自 *concatenate*，接起来。`x/y` 是两排旧格子，`z` 是接完的新排；`len_x/len_y` 是两段长度，`k` 是正在处理的下标。 |
| 3.5 反转数组 | `array`、`left`、`right`、`tmp` | `left/right` 是要交换的格号，`tmp` 临时保管旧值。5格时，先换1和5，再换2和4。 |
| 3.6 用值当下标 | `sumArray`、`a`、`b`、`n`、`x`、`i` | 把 `b` 想成一张「要去哪些格」的清单。`i` 扫清单，`n` 是清单长度；`a[b[i]]` 先从 `b[i]` 拿格号，再去 `a` 取值，交给 `x` 累加。 |
| 3.7 最大公约数 | `gcd`、`a`、`b`、`m`、`n` | `gcd` 是 *greatest common divisor*，最大公约数。`a/b` 是起始两个数，`m/n` 是拿来反复相减的两个工作值。 |
| 3.8 插入第 k 项 | `sort`、`data`、`k`、`i`、`tmp` | `k` 指本次要处理第几项；`i` 指当前比较或移动到哪里；`tmp` 暂存要交换的数。看题时把「待插入的位置」和「正在比较的位置」分开。 |
| 3.9 查找链表 | `search`、`Node`、`top`、`node`、`key`、`next` | `Node` 是节点类，`top` 是入口，`node` 是你手指当前指着的节点，`key` 是要找的字符。`node ← node.next` 就是把手指挪到下一站。 |
| 3.10 二维数组查找 | `arraySearch`、`arraySearch_v2`、`mdata`、`n`、`i/j`、`i_max/j_max` | `mdata` 是二维数据，`n` 是目标值。`i/j` 定位当前格，`i_max/j_max` 告诉你行列最多能走到哪里。`_v2` 是同一任务的另一版实现。 |
| 3.11 跟踪数组变化 | `data`、`i`、`j`、`tmp` | `data` 是那排会被改写的格子。`i/j` 说的是位置，真正被拿出、暂存、写回的是格子里的值。 |
| 3.12 数字字符转整数 | `strToInt`、`charToInt`、`strToInt2_v2`、`str/str2`、`p`、`code`、`i`、`n`、`tmp`、`val`、`valArray` | `To` 读成「变成」。`str/str2` 是输入；`p` 是交给 `charToInt` 的单个字符，`code` 是字符对照表。`i` 扫输入，`n` 是长度；`tmp` 存临时值，`val` 存整数结果，`valArray` 存逐个转换后的数。 |
| 3.13 十进制转二进制 | `decToBin`、`decToBin_v2`、`n`、`bin`、`j`、`k` | `dec/bin` 来自 *decimal/binary*。`n` 是原始数，`j` 是反复除以2的工作值，`bin` 是放各位的数组，`k` 帮你定位要写哪一位。 |
| 3.14 显示位运算 | `bitOR`、`a`、`b`、`c`、`mask`、`i` | `bitOR` 是按位或；`a/b` 是输入，`c` 是计算结果。`mask` 像只有一个孔的遮板：和它按位与时，只有那个孔对应的位保留下来；`i` 数处理了几轮。 |
| 3.15 递归 | `F`、`fact`、`proc`、`gcd`、`n`、`m` | `F` 按题目给的规则算，`fact` 是阶乘，`gcd` 是最大公约数。第119页的 `proc(n)` 里，每一层都有自己的 `n`，所以回来时，打印的还是这一层原来收到的数。 |

## 第4章：应用例题

| 题号 | 名字 | 原意与读题方式 |
|---|---|---|
| 4.1 游戏得分 | `calcScore`、`num`、`mark`、`mc`、`markCT`、`n`、`i`、`score` | `calcScore` 是算总分；`mark[i]` 是这次读到的游戏标记；`num(mc)` 负责把单个数字字符变成数值，`n` 是在 `markCT` 对照表里查到的位置；`score` 像记分牌，边读边加。 |
| 4.2 奇数阶幻方 | `magicSquare`、`square`、`n`、`i`、`j`、`k` | `magicSquare` 是填幻方，`square` 是那张方格纸；`n` 是边长，`i/j` 是笔尖所在的行列，`k` 是现在要填进去的数字。 |
| 4.3 累计天数 | `isLeapYear`、`year`、`leapyear`、`elapsedDays`、`y/m/d`、`mdays`、`i`、`days` | `isLeapYear(year)` 判这个年份是不是闰年，`leapyear` 保存判定用的整数值。`y/m/d` 是年月日；`mdays` 像一张每月天数表；`i` 扫前面的月份，`days` 把那些月的天数和本月已过的天数加起来。 |
| 4.4 筛素数 | `primeNumber`、`prime`、`sqrt`、`n`、`m`、`i`、`j` | `sqrt` 是平方根。`n` 是筛到多大，`m` 是平方根去掉小数后的上限。`i` 是拿来筛的数，`j` 是它的倍数。把 `prime` 看成打叉表：**`prime[j] = 1` 是给 j 打叉，表示它不是素数。** |
| 4.5 霍夫曼编码 | `A/B/C/D`、`BC/DB/DBC` 等 | 单个字母是原来的符号；`BC` 这样的名字是合并后的节点标签。看树时，出现次数用来决定先合并谁，线上的 `0/1` 才用来读编码。 |
| 4.6 合并有序数组 | `merge`、`slist1/2`、`num1/2`、`list`、`i/j/k` | `merge` 是合并。想象三根手指：`i` 指第一排还没取的数，`j` 指第二排还没取的数，`k` 指新排 `list` 的下一个写入位置。`num1/2` 是两排各自的长度。 |
| 4.7 压缩字符串 | `compression`、`S`、`P`、`i`、`c` | `S` 是压缩前，`P` 是压缩后；`i` 指读到哪里，`c` 记「这个字符连续出现了几次」。换了字符，就要处理前一段的计数。 |
| 4.8 哈希登记 | `hash`、`hashTbl`、`data`、`idx`、`i`、`h`、`k` | `hashTbl` 是登记表；`i` 从 `data` 里取这次要登记的数。`h` 是目前查到的表位置，撞到已有数据就沿链接找；`k` 记刚才经过的位置，`idx` 是可用的溢出格号。 |
| 4.9 创建堆 | `makeHeap`、`heap`、`n`、`num`、`r`、`p`、`swap`、`i/j`、`tmp` | `heap` 是堆数组，`n` 是已有几个数，`num` 是新来的数。`r` 像跟着新数往上走的手指，`p` 指它的父节点；`swap(i,j)` 用 `tmp` 把指定两格的值换过来。 |
| 4.10 递归操作栈 | `proc`、`stack`、`push(n,val)`、`pop(n)`、`empty(n)`、`A/B/C` | `n` 在这里是第几个栈，`val` 才是放入的数。`push(3,pop(1))` 就是从A拿一个，放进C。**本题规定栈空时 `empty` 返回0。** 往下调用时搬 A→C，回来时搬 C→B。 |
| 4.11 枚举二进制 | `test`、`numberOfDigits`、`n`、`binaryNumber`、`k`、`bin`、`printBin`、`i` | `numberOfDigits` 是总共填几格，保存到 `n`。`binaryNumber(k)` 是「现在轮到第 k 格」，`bin` 就是那排格子。格子填完才调用 `printBin()`，用 `i` 从左到右打印。 |
| 4.12 二叉搜索树查找 | `lookup`、`lookup_v2`、`btree`、`val`、`t` | `val` 是想找的数字，`t` 是现在站的节点**编号**。`btree[t]` 像一张三栏卡片：第1栏写自己有多大，第2栏写左边去哪，第3栏写右边去哪。 |
| 4.13 逆波兰表达式 | `rpnCalc`、`rpn`、`tbl`、`RpnCalcStack`、`rpnStack`、`i`、`k`、`x`、`y`、`push(n)`、`pop()`、`proc(n)` | `RPN` 是逆波兰表示法，`Calc` 是计算。`i` 盯输入，`k` 跑对照表。例如 `i=3` 读到乘号，查到 `k=12` 才知道做乘法。`rpnStack` 是存数字和中间结果的栈；先拿出的是右边的 `y`，后拿出的是左边的 `x`。`push(n)` 的 `n` 是放入的值；专栏 `proc(n)` 的 `n` 是算术树节点。 |
| 4.14 自组织链表 | `organizingSearch`、`Node`、`first`、`current`、`temp`、`key`、`value`、`next` | `first` 是入口，`current` 是手指当前指着的节点，`temp` 记它前面是谁。找 `"C"` 时 `current` 指C、`temp` 指B；用 `key` 对字符，返回的是C盒子里的 `value = 17`。 |
| 4.15 邻接矩阵遍历 | `graphSearch`、`matrix`、`visit`、`n`、`node`、`j`、`Vᵢ/Vⱼ` | `Vᵢ` 是编号 i 的圆圈。`n` 是圆圈总数，`node` 是你现在站的房间，`j` 是正在问「能不能过去」的房间。`matrix[node,j]` 问有没有直连，`visit[j]` 问以前去过没有。 |
| 4.16 二进制乘法 | `binMultiply`、`m`、`n`、`x`、`y`、`z`、`i` | `m/n` 是原输入，`x` 是本轮可以加的数，`y` 最右一位像开关：1就加，0就不加；`z` 是已经加了多少，`i` 数轮次。 |
| 4.17 Base64 位分组 | `data`、`encode`、`a～x` | `data` 是三个8位旧盒子，`encode` 是四个8位新盒子，每盒只在右边装6个原始位。解析里的 `a～x` 是24个位的位置标签。`∨` 能拼接，是因为两段已经摆好，每段所在位置在另一排都是0。 |

### 三、链表里最容易混：入口、手指、盒子里的箭头

| 名字 | 本书里的用法 | 一句话读懂 |
|---|---|---|
| `first`、`First`、`listHead`、`top` | 数组链表的 `First` 存首节点**下标**；类实现的 `first/listHead` 存首节点**引用**；3.9 也用 `top` 表示链表入口。 | 都可以先叫“入口”。但要确认它是数字编号，还是直接指向节点。 |

#### 四个赋值看着很像，改的却是四样东西

| 代码 | 右边先读到什么 | 左边实际改了什么 |
|---|---|---|
| `prev ← prev.next` | 下一节点的引用 | 改 `prev` 指到哪；链表连线没变。 |
| `prev.next ← curr` | 新节点的引用 | 改旧尾节点的下一站；新节点接进来。 |
| `prev.next ← prev.next.next` | 原先往后两站的节点 | 改连线，让它跳过中间那个节点。 |
| `first ← current` | 当前节点的引用 | 改链表从哪里开始；这一行本身不改任何节点的 `next`。 |

例：4.14 找到 C，原来是 `A → B → C → D`。

```text
temp.next ← current.next   // B 的下一站从 C 改成 D。
current.next ← first       // C 的下一站改成 A；入口此时还是 A。
first ← current            // 入口改到 C；现在从 C 开始走。
```

### 四、下标、内容和边界：数字一样，也可能是不同东西

| 代码或名字 | 怎样分清 |
|---|---|
| `right` 与 `array[right]` | `right = 5` 是第5格；`array[right] = 1` 是第5格里装着1。反转之后，格号不变，内容可以变。 |
| `left/right` 在数组题和树题里 | 反转数组时是两个待交换的格号；二叉树里是左、右孩子的位置或引用。看到 `t.left`，读成“节点 t 的左孩子”。 |
| `mid`、`middle` 与 `T[mid]`、`data[middle]` | `mid/middle` 是位置；带数组名的是这个位置里的值。二分查找先算位置，再拿格子里的值和目标比。 |
| `low`、`high` | 是待查区间的两个下标边界。若 `middle` 已经等于 `low`，再写 `low ← middle` 就没动，循环可能卡在同一轮。 |
| `a[b[i]]` | 从里往外读。假设 `i = 2`、`b[2] = 5`，下一步读的是 `a[5]`，不是 `a[2]`。 |
| `matrix[node,j]` 与 `visit[j]` | 4.15 中，前者问 `node` 和 `j` 有无直连；后者问 `j` 去没去过。**有路且没去过**，才递归走过去。 |
| `Vᵢ`、`Vⱼ` 与 `matrix[i,j]` | `V₂` 是2号节点，`V₄` 是4号节点；`matrix[2,4]` 是拿第2行、第4列去问“这两点有没有直连”。圆圈的编号与格子里填的 `0/1` 是两回事。 |
| `matrix`、`matrixN`、`sparseMatrix` | 4.15 的 `matrix` 装有无边；4.20 的 `matrix` 装转移概率，`matrixN` 装算出的矩阵；第249页的 `sparseMatrix` 用三组数据记非零项的行、列、值。 |
| `btree[t][1]`、`btree[t][2]`、`btree[t][3]` | 4.12 先用 `t` 找到节点记录。第一格是拿来比较的**值**，第二格和第三格是接下来去哪的**编号**。 |
| `idx`、`pos`、`i` | 4.8 的 `idx` 指可用的溢出位置；删除链表题的 `pos` 是要删第几个；`i` 是循环里当前走到第几步。 |
| `len_x` 与 `x[len_x]` | 前者是数组长度。下标从1开始且数组非空时，后者才是最后一个元素；下标从0开始，最后一个下标是 `len_x−1`。 |
| `0`、`−1`、`未定义` | 不同题有不同用法。第30页节点的 `next = 0` 表示走完；4.12 孩子编号 `−1` 表示没有孩子；第248页的 `.next` 未定义表示没有后继。4.15 的 `visit[j] = 0` 却表示尚未访问。 |

## 4.1　计算游戏得分

**【第122页：例题】**

从选项中选择填入空白处的正确答案。数组下标从1开始。

函数calcScore接收保存游戏结果的字符型数组mark，根据其中的内容计算总得分并返回。

游戏由多个回合组成，每回合的结果用以下字符表示：

```text
"1", "2", "3", "4", "5", "6", "7", "8", "9", "+", "−"
```

数组mark按照以下规则，依次保存第1回合到最后一回合的结果。

**规则**

1. 第1回合的结果，是`"1"`～`"9"`或`"+"`中的任意一个。
2. 最后一回合的结果，是`"1"`～`"9"`中的任意一个。
3. 结果为`"+"`的回合，其后一个回合的结果一定是`"1"`～`"9"`；结果为`"−"`的回合，其前一个回合的结果一定是`"1"`～`"9"`。

以下列形式调用calcScore时，总得分，也就是返回值为41：

```text
calcScore({"1", "+", "2", "−", "3", "【空白】", "5"})
```

**【第123页：程序与选项】**

```text
○整数型：num(字符型：mc)
    字符型的数组：markCT ←
        {"1", "2", "3", "4", "5", "6", "7", "8", "9"}
    整数型：n ← 1

    while (mc ≠ markCT[n])
        n ← n + 1
    endwhile

    return n

○整数型：calcScore(字符型的数组：mark)
    整数型：i
    整数型：score ← 0

    for (i从1到mark的元素个数，每次增加1)
        if (mark[i] = "+")
            score ← score + num(mark[i + 1]) + 10
        elseif (mark[i] = "−")
            score ← score + num(mark[i − 1]) + 10
        else
            score ← score + num(mark[i])
        endif
    endfor

    return score
```

$$
\frac{n^2(n^2+1)}{2}\div n
=\frac{n(n^2+1)}{2}
$$

每列以及两条对角线之和，也都是这个值。

例如3×3幻方：

$$
3\times(3^2+1)\div2=15
$$

$$

$$

将其中的n替换为n²，就得到1到n²的总和公式。

**霍夫曼编码**，是给经常出现的符号分配较短的编码，给较少出现的符号分配较长的编码，从而压缩整个序列的方法。

为了生成编码，先按以下步骤创建霍夫曼树。

**霍夫曼树的创建步骤**

```text
1. 按出现次数从多到少排列各符号。次数相同的符号，先后顺序不限。
2. 选择出现次数最少和次少的两个符号，将它们作为叶节点，创建共同的父节点：
   - 父节点的次数，为这两个符号次数之和。
   - 从父节点通向出现次数较少者的边，标记为1。
   - 另一条边标记为0。
3. 将新节点视为一个新符号，重复步骤2，直到无法再创建新的节点。
```

从最终树的根节点出发，到某个符号为止，沿途各条边上的0、1依次排列，就是该符号的霍夫曼编码。

### 4.6　合并已经排好序的数组

例题
从选项中选择适合填入下列说明中【a】、【b】的正确答案。数组的元素编号从1开始。

函数 merge 接收两个已经按升序排列的整数型数组 slist1、slist2，将它们合并成一个按升序排列的数组 list，并返回该数组。

但是，程序中标有 α、β 的 while 语句的条件式有误。

merge({2, 4, 6, 10, 15}, {6, 11, 17, 25})

##### 程序

```text
    while ((i ≤ num1) and (j ≤ num2))

        else

```

```text
    while (i < num1)                 /* α */
        list[k] ← slist1[i]
        i ← i＋1

    endwhile
```

##### 选项

| 选项 | a | b |

解析
答案：エ

merge 是将两个数据序列合并的处理。本题把两个已经按升序排列的数据序列，一边比较数据的大小，一边合并为一个按升序排列的数据序列。

```text
将数据序列A、B合并成数据序列C的基本算法如下。
1. 分别从A、B取出一个数据，记为 a、b。
2. 在A、B中的任意一个序列尚未取完之前，重复下列操作。
   - 如果 a < b，就把 a 输出到C，再从A取出下一个数据。
   - 否则，把 b 输出到C，再从B取出下一个数据。
3. 把尚未取完的序列中的剩余数据，依次输出到C。
程序中的 num1、num2 分别表示两个输入数组的元素个数。i、j 是输入数组的元素编号，k 是输出数组 list 的元素编号。
第一个while语句的处理
while ((i ≤ num1) and (j ≤ num2))
```

这个循环在两个数组都还有未处理元素时继续执行。循环结束意味着：
(i > num1) or (j > num2)

也就是两个数组中的某一个已经全部处理完毕。
脚注1：求循环结束条件时，要对循环继续条件取反。这里可以使用第52页介绍的德摩根定律。

循环内部比较 slist1[i] 和 slist2[j]：
- slist1[i] 较小时，将它存入 list[k]，然后使 i 加1。
- 否则，将 slist2[j] 存入 list[k]，然后使 j 加1。
- 每存入一个数据，k 都加1。
α、β的处理
第一个循环结束后，某一个输入数组中可能还有剩余数据。α、β两个循环就是把剩余数据依次存入 list。

已经处理完的数组不会进入对应的循环；只有尚未处理完的数组才会继续执行复制操作。

但是，数组最后一个元素的编号分别是 num1、num2。程序却使用：
i < num1
j < num2

因此，i 等于 num1 或 j 等于 num2 时，循环就会结束。也就是说，尚未处理完的数组的最后一个元素会被漏掉。

下面跟踪第一个循环的执行过程。
slist1 = {2, 4, 6, 10, 15}
slist2 = {6, 11, 17, 25}

num1 = 5
num2 = 4

| i | j | k | 比较 | 执行的主要处理 |
| --- | --- | --- | --- | --- |
| 1 | 1 | 1 | 2 < 6 | list[1] ← slist1[1]，i加1 |
| 2 | 1 | 2 | 4 < 6 | list[2] ← slist1[2]，i加1 |
| 3 | 1 | 3 | 6 = 6 | list[3] ← slist2[1]，j加1 |
| 3 | 2 | 4 | 6 < 11 | list[4] ← slist1[3]，i加1 |
| 4 | 2 | 5 | 10 < 11 | list[5] ← slist1[4]，i加1 |
| 5 | 2 | 6 | 15 > 11 | list[6] ← slist2[2]，j加1 |
| 5 | 3 | 7 | 15 < 17 | list[7] ← slist1[5]，i加1 |

```text
表中省略了每次循环末尾的 k ← k＋1。
```

此时 i 变为6，大于 num1，所以第一个循环结束。

剩余的是：
slist2[3] = 17
slist2[4] = 25

β的条件为 j < num2，因此只会复制 slist2[3]，不会复制 slist2[4]。

所以，未被存入 list 的是数组 slist2 中编号为4的元素。

```text
正确的条件应为：
while (i ≤ num1)
```

```text
以及：
while (j ≤ num2)
```

补充
也可以不逐行跟踪整个程序，而是通过两个数组中的数据大小关系来判断。

slist2 中的6、11都小于 slist1 的最后一个值15，因此会在第一个循环中被存入 list。另一方面，slist1 的所有值都小于 slist2 的最后一个值25，因此 slist1 会先全部处理完。

由此可知，剩余的是 slist2，被漏掉的就是它的最后一个元素25。

##### 专栏：使用哨兵的合并处理

还可以在两个数组末尾分别添加一个大于所有实际数据的值 max，将其作为哨兵。
slist1 = {2, 4, 6, 10, 15, max}
slist2 = {6, 11, 17, 25, max}

这时，将循环条件改为：
(slist1[i] ≠ max) or (slist2[j] ≠ max)

```text
也就是只要两个数组的当前位置还没有同时到达哨兵，就继续处理。
整数型: i ← 1, j ← 1, k ← 1
```

```text
while ((slist1[i] ≠ max) or (slist2[j] ≠ max))
    if (slist1[i] < slist2[j])
        list[k] ← slist1[i]
        i ← i＋1
    else
        list[k] ← slist2[j]
        j ← j＋1
    endif
    k ← k＋1
endwhile
```

某一个数组先到达哨兵后，另一个数组中剩余的实际数据都小于 max，因此会自然地被依次选中并存入 list。

这样就不再需要α、β两个处理剩余数据的循环。

### 4.8　使用哈希法登记数据

过程 hash 接收由正整数构成的整数型数组，使用哈希法将数据登记到表中。

哈希法通过哈希函数，将数据转换成一定范围内的哈希值，再根据该值确定存储位置。

本题使用的哈希函数为：
哈希值 = 整数数据除以5的余数＋1

不同数据的哈希值相同时，使用链式方法将这些数据连接起来。

全局二维整数型数组 hashTbl 有15行、2列，所有元素的初始值均为0。
- 第1列存储整数数据。
- 第2列存储链，即后继数据所在的行号。
- 第1～5行存储各哈希值对应的第一个数据。
- 哈希值相同的第2个及之后的数据，按照出现顺序，依次存入第6行及之后的位置。

递归程序的特点
- 递归程序一定有结束递归调用的条件，即不再继续调用自身、而是返回调用方的条件，称为递归出口。
- 在到达递归出口之前，程序不断调用自身；到达递归出口后，再逐层返回调用方。
在本题的 proc 中，递归出口的条件是：
empty(1)的返回值等于0

函数 empty 检查参数指定的栈是否为空，空时返回0，不空时返回1。

参数值用于识别栈：
1：栈A
2：栈B
3：栈C

因此，栈A不为空时继续调用自身，栈A为空时返回调用方。

在跟踪程序之前，先确认两条语句的作用。
push(3, pop(1))

push(2, pop(3))

从栈C弹出一个值，再将该值压入栈B。
到达递归出口之前
过程 proc 先把从A弹出的值压入C，然后调用自身。这个过程重复执行，直到A为空。

| --- | --- | --- |
| 初始状态 | {1, 2, 3} | {1, 2, 3} |
| 第1次调用：将3从A移到C | {1, 2} | {1, 2, 3, 3} |
| 第2次调用：将2从A移到C | {1} | {1, 2, 3, 3, 2} |
| 第3次调用：将1从A移到C | {} | {1, 2, 3, 3, 2, 1} |
| 第4次调用：到达递归出口 | {} | {1, 2, 3, 3, 2, 1} |

当栈A为空时，if 的真分支什么也不做，随后过程结束，返回调用方。
从递归出口返回之后
到达递归出口，也就是A为空后，开始逐层返回，并执行：
push(2, pop(3))

下面将这条语句称为“处理α”。
- 从第4次调用返回后，在第3次调用中执行处理α。
- 从第3次调用返回后，在第2次调用中执行处理α。
- 从第2次调用返回后，在第1次调用中执行处理α。
栈B的初始状态为：
{1, 2, 3}

处理α执行三次，将C栈顶的1、2、3依次移入B。

| 返回阶段 | 从C弹出的值 | 栈B | 栈C |
| --- | --- | --- | --- |
| 递归出口处 | — | {1, 2, 3} | {1, 2, 3, 3, 2, 1} |
| 返回第3次调用并执行α | 1 | {1, 2, 3, 1} | {1, 2, 3, 3, 2} |
| 返回第2次调用并执行α | 2 | {1, 2, 3, 1, 2} | {1, 2, 3, 3} |
| 返回第1次调用并执行α | 3 | {1, 2, 3, 1, 2, 3} | {1, 2, 3} |

因此，最终栈B的状态为：
{1, 2, 3, 1, 2, 3}

其中后面三个值1、2、3是这次处理新压入的值。

实际上，if 语句中与条件对应的处理，可以是由0条或更多语句组成的语句集合。

“0条或更多”意味着什么都不写也可以。

本例输出全部n位二进制数，由三个过程构成。最先调用的是test。它将参数指定的值赋给全局变量n，再调用binaryNumber(1)。n表示二进制数的位数，所以test(4)会输出全部4位二进制数。

本题的关键是理解binaryNumber。它设置从左端数起第k位的值。从binaryNumber(1)开始，程序一边递归调用自身，一边从第1位开始依次设置数组bin。到达递归出口后，printBin输出bin的内容。

- test：设置n，调用binaryNumber(1)。
- binaryNumber：`k > n`是递归出口；否则设置第k位，并继续处理下一位。
- printBin：按顺序输出bin[1]～bin[n]，再换行。

再看n=2。原图中的实线箭头表示调用，虚线箭头表示从调用返回；空格表示未定义值，彩色数字表示刚刚设置的值。调用顺序①～⑥如下：

|4|14|−1|−1|

### 专栏：将lookup改写为递归版本

本题lookup使用while查找。但是，包括二叉搜索树在内的二叉树具有递归结构，因此也可以使用递归调用。

下面是递归版本lookup_v2。第一个参数val是查找值，第二个参数t是当前查找对象——二叉搜索树根节点的元素编号。`t等于−1`是递归出口。

```text
○逻辑型: lookup_v2(整数型: val, 整数型: t)
    if (t等于−1)                    /* 递归出口 */
        return false
    endif
    if (val等于btree[t][1])
        return true
    elseif (val小于btree[t][1])
        return lookup_v2(val, btree[t][2])
    else
        return lookup_v2(val, btree[t][3])
    endif
```

特点在于：比较查找值和当前树的根节点值；查找值较小时，将左子树作为下一次的查找对象；较大时，将右子树作为下一次的查找对象。

例如调用lookup_v2(11,1)，最初对象是以节点1为根的整棵树。11小于根值13，所以接下来查找节点1的左子树，也就是以节点2为根的树。程序通过`lookup_v2(val, btree[t][2])`调用自身，此时实际调用为lookup_v2(11,2)。

在以节点2为根的树中，11大于根值10，因此改查右子树，通过`lookup_v2(val, btree[t][3])`递归调用。此时val=11、t=2，实际调用为lookup_v2(11,−1)。因为不存在右子树，t为−1，到达递归出口。

然后依次返回调用方，返回值都是false：

```text
lookup_v2(11,1)
  → lookup_v2(11,2)
    → lookup_v2(11,−1)：返回false
    ← 返回false
  ← 返回false
```

rpnCalc处理逆波兰表示法的表达式，求其值。逆波兰表示法将运算符写在运算对象——操作数的后面，因此也称后缀表示法。例如“1＋2”写成“1 2 ＋”；“1＋2×3”是将1与2、3的乘积相加，所以写成“1 2 3 × ＋”。

> 脚注1：普通表达式转换为逆波兰表达式的方法参见本节末尾专栏（第187页）。

关键是如何处理这种表达式。请记住：可以**使用栈，从左向右求值**。规则如下：

1. 遇到数值，将其压栈。
2. 遇到运算符，从栈中弹出一个值，再弹出一个值；以后弹出的值作为左操作数、先弹出的值作为右操作数进行运算，将结果重新压栈。

例如“1 2 3 × ＋”：

|读入内容|处理|栈（左为底，右为顶）|
|---|---|---|
|1|压入1|{1}|
|2|压入2|{1,2}|
|3|压入3|{1,2,3}|
|×|弹出3和2，压入2×3=6|{1,6}|
|＋|弹出6和1，压入1＋6=7|{7}|

本题使用RpnCalcStack类实现栈，但阅读时不要被类的写法干扰。将`rpnStack.push`直接看成push，将`rpnStack.pop`看成pop，再与上述步骤对照即可。类的说明见后面的补充。

本题数组从0开始，因此for语句是“i从0增加到rpn元素个数－1”。考试多数题目下标从1开始，但也可能有从0开始的题目，请注意题目条件。

for从rpn[0]依次处理到最后一个元素。rpn存储的是字符，进入for后首先通过while在tbl中寻找相同字符，将它转换成编号k：字符“0”～“9”对应数值0～9；运算符“＋”“−”“×”“÷”分别对应10、11、12、13。例如rpn为{"1","2","＋"}时，k依次为1、2、10。

while之后的if实现上述求值规则。k为0～9时，将数字字符转换后的数值k压栈；k大于9时，根据其值选择四则运算，将两个弹出的值运算后重新压栈。

**a、b：**程序压入的是“x 运算符 y”。加法和乘法满足交换律，两个弹出值赋给x、y的先后无关紧要；减法和除法不满足交换律，必须先弹出的值赋给y，后弹出的值赋给x。

例如“2 1 −”表示2−1：先弹出1赋给y，再弹出2赋给x，压入x−y=1。因此a为y、b为x。

**c：**处理完最后一个元素rpn[rpn元素个数－1]后，栈中剩下的值就是整个表达式的值。将它弹出并返回即可，故c为`rpnStack.pop()`。

> 脚注2：交换律指交换操作数的位置后，计算结果不变。例如1＋2=2＋1、3×4=4×3，加法和乘法都满足交换律。

**补充：类与实例。**用RpnCalcStack实现栈时，需要生成该类的实例（实体）：

```text
RpnCalcStack: rpnStack ← RpnCalcStack()
```

这条语句先准备RpnCalcStack类型的变量rpnStack，再把RpnCalcStack()生成的实例的“引用”赋给它。之后就能通过变量rpnStack调用push、pop方法。例如`rpnStack.push(10)`访问的是rpnStack引用的实例中的push。

题目中的构造函数RpnCalcStack是一种用于生成实例的特殊方法。它初始化新创建的实例，创建空栈。

> 脚注3：原书为区别普通的“参阅”，给技术意义的“引用”加上引号。看到这里的“引用”，可以理解为实例所在的位置。

### 专栏：将普通表达式转换为逆波兰表示法

日常使用的表达式可以表示成一种称为**算术树**的二叉树。例如1＋2×3，根为“＋”，左子节点为1，右子节点为“×”；“×”的左右子节点分别为2、3。也就是先将2、3相乘，再与1相加。

对这棵树进行深度优先的**后序遍历**，就能得到逆波兰表达式。下面是简化程序：

```text
○proc(节点n)
    如果节点n有左子节点L，则调用proc(L)
    如果节点n有右子节点R，则调用proc(R)
    输出节点n的值
```

特点是先递归处理左右子节点，再处理自己，即输出节点值。因此得到后序顺序“1 2 3 × ＋”。原图中的圆点表示输出节点值的时机。

若把“输出节点n的值”放在处理左子节点之后、右子节点之前，就变为**中序遍历**，输出通常的表达式“1＋2×3”。若放在处理左子节点之前，则变为**前序遍历**，输出“＋ 1 × 2 3”。这种将运算符写在操作数前面的表示方法，称为波兰表示法，也叫前缀表示法。

### 解析

**答案：エ。**

organizingSearch进行自组织查找，将找到的数据移到开头。目的是提高查找效率。从头逐个检查的顺序查找，对位置靠后的数据需要花费更多时间。自组织查找利用“一次被查找的数据，再次被查找的可能性较高”这一点，将经常查找的数据移向前方。

本函数从first引用的首元素开始，依次寻找与key相同的元素。这里使用current：先将first赋给current，如果key与current.key不一致，就执行`current ← current.next`检查下一元素。

找到一致元素后，将current引用的元素移到开头。不过，如果current等于first，说明它已经是首元素，不必移动。因此只有current不等于first时，才执行图中的“处理A”，即含a～c的三条语句。

> 脚注1：从首元素依次向后查找，是链表查找的常见处理，请记住。
>
> 脚注2：技术意义的“引用”可理解为元素所在的位置。

例如key="C"时，匹配的是第3个元素。考虑移动元素时，把“哪些位置应该怎样连接”画成图，会更容易理解。原图灰色箭头表示移动前的连接，①②③表示处理顺序。

**移动到开头的处理：**

1. 将current元素的next赋给它的前一个元素的next，即让B直接连接D。
2. 将first赋给current元素的next，即让C连接原首元素A。
3. 将current赋给first，即让C成为新首元素。

**a：**`【a】 ← current.next`对应步骤1，因此应填“current前一个元素的next”。注意，每次current向后移动前，先执行了`temp ← current`，所以temp始终保存current前一个元素的引用。因此a为`temp.next`。

**b：**`current.next ← 【b】`对应步骤2，所以b为`first`。

**c：**`first ← 【c】`对应步骤3，所以c为`current`。

### 专栏：链表的自组织由两个操作组成！

自组织查找将找到的元素移到链表开头。所谓移动到开头，可分成两个操作：

- 从原链表中摘下找到的元素。
- 将摘下的元素添加到链表开头。

仍以查找值C为例，依次确认。

**先摘下C。**找到的是第3个元素。把它摘下，意味着将B的下一个元素改为D。因此，需要把C.next的值赋给B.next。

例如，D元素的引用为400，则C.next为400。将400赋给B.next，就得到A→B→D→E，C不再位于这条链上。

> 脚注3：这里的“引用”仍可理解为元素所在的位置。

**再将C添加到开头。**假设A元素的引用为100，C元素的引用为300。此时first=100，链表为A→B→D→E，C已经摘下。

要让C成为首元素，需要让first引用C，并让C后面接上原首元素A。首先把first的值100赋给C.next，C就连接到A；然后把C的引用300赋给first，C就成为首元素。

最后得到：C→A→B→D→E。

以上就是自组织处理。这与解析中的“移动到开头”是同一操作，请再读一遍解析，以加深理解。链表操作最初会觉得难，但熟悉后就能顺利处理。继续努力吧！

1. 画出邻接矩阵表示的图。
2. 判断使用的是深度优先还是广度优先遍历。

先画图。第i行第j列和第j行第i列的值相同。如果Vi和Vj之间有边，两处都是1。因此，只需检查主对角线右上方或左下方值为1的元素。

> 脚注3：graphSearch没有明写递归出口条件，但for结束后就会返回调用方。

> 脚注4：参见“1.6.2 二叉树的遍历”（第36页）。


1. 若y最低位为1，将x加到z。
2. 将x左移1位。

过程circleRatio使用蒙特卡罗法近似计算圆周率。蒙特卡罗法是使用随机数、即概率，求所需解或规律的近似值的一类方法的统称。

求π近似值时，考虑边长r的正方形及其中的四分之一圆，在正方形内使用随机数均匀地打入大量点。正方形和四分之一圆的面积之比，应与落入其中的点数成比例，因此：

```text
总点数 : 四分之一圆内点数 = r² : (πr²×1/4)
```

正方形面积为r²，四分之一圆面积为πr²×1/4。由这个比例式求π。

```text
        endif

    输出【b】的值
```

## 4.19　思考使用二分法求近似解的步骤（第212～215页）

### 例题

从选项中选择a～d的正确组合。

一次方程以外的方程称为非线性方程。非线性方程通常没有通用的求解公式，这时可用近似计算方法求近似解。这里考虑有代表性的二分法。

二分法基于介值定理：若f(x)在闭区间[a,b]上连续，且f(a)≠f(b)，则对f(a)、f(b)之间的任意数k，至少存在一个c（a<c<b），使k=f(c)。因此，当f(a)、f(b)异号，即f(a)×f(b)<0时，存在使f(c)=0的c。利用这一性质求非线性方程f(x)=0近似解的方法，称为二分法。

二分法反复将包含解的闭区间二等分，判断解在哪一半，逐步缩小区间，求出近似解。

**步骤：**

1. 找到满足f(a)×f(b)<0的区间[a,b]。
2. 求中点m=(a＋b)÷2。
3. 若f(a)×f(m)<0，解在m的【a】侧，用m替换b，将区间缩至【a】半部分。若f(m)×f(b)<0，解在m的【b】侧，用m替换a，将区间缩至【b】半部分。
4. 重复步骤2、3，直到区间宽度足够小，然后以m作为近似解结束。

每次区间宽度减半。最初宽度为d₀，重复n次后的宽度为：

```text
dₙ = d₀×【c】
```

当区间宽度dₙ足够小而结束时：

```text
近似误差 < 【d】
```

|选项|a|b|c|d|
|---|---|---|---|---|
|ア|左|右|2⁻ⁿ|dₙ|
|イ|左|右|2⁻ⁿ|m|
|ウ|左|右|2ⁿ|2ⁿ|
|エ|右|左|2⁻ⁿ|dₙ|
|オ|右|左|2⁻ⁿ|m|
|カ|右|左|2ⁿ|2ⁿ|

### 解析

**答案：ア。**

这是一道使用二分法进行近似计算的题目。不要一看到“二分法、近似计算”就觉得难。想象一个存在f(x)=0解的具体函数图像，按题目给出的步骤冷静思考。

**a、b：**原图以一条穿过x轴的连续曲线说明。

1. 初始选择[a,b]，满足f(a)×f(b)<0。图中f(a)<0、f(b)>0，因此区间内有解。
2. 求中点m=(a＋b)÷2。
3. 如果f(a)<0、f(m)>0，则f(a)×f(m)<0，解存在于a和m之间，即m的左侧。将b替换为m，下一段区间是[a,m]。

另一幅图中f(m)×f(b)<0，解在m、b之间，即m的右侧。将a替换为m，下一段区间是[m,b]。因此a为左、b为右。

**c：**每次宽度减半。第1次为d₀/2，第2次为d₀/2²，第3次为d₀/2³，因此n次后：

$$d_n=d_0\frac{1}{2^n}=d_0\times2^{-n}$$

所以c为2⁻ⁿ。

**d：**近似误差指结束时的近似解m与真实解α之间的差的大小。设最终区间为[aₙ,bₙ]，宽度为dₙ，真实解α位于其中。

本步骤中的m是前一区间[aₙ₋₁,bₙ₋₁]的中点。若f(aₙ₋₁)×f(m)<0，就将m设为bₙ；若f(m)×f(bₙ₋₁)<0，就将m设为aₙ。因此，作为近似解的m等于最终区间的某一个端点。

也就是，真实解位于[aₙ,bₙ(=m)]或[aₙ(=m),bₙ]中，误差小于区间宽度|aₙ−bₙ|=dₙ。因此d为dₙ。

## 4.21　使用最小二乘法求回归方程（第222～227页）

### 例题

选择程序a、b的正确组合。数组下标从1开始。

回归分析是需求预测常用的方法之一。它研究观测值xᵢ、yᵢ（i=1,2,…,n）之间的关系，求出最符合观测数据的直线或曲线。

当观测值之间的关系可以用直线方程y=ax＋b表示时，过程regressionEquation使用最小二乘法求回归方程的系数a、b。

**求a、b的步骤：**设观测值xᵢ对应的回归预测值为Yᵢ，它与实际yᵢ的差为εᵢ：

$$\varepsilon_i=y_i-Y_i=y_i-(ax_i+b)$$

设差的平方和，即残差平方和，为s，观测点数为n：

$$s=\sum_{i=1}^{n}\varepsilon_i^2=\sum_{i=1}^{n}(y_i-ax_i-b)^2$$

要求使s最小的a、b，对s求偏导并令：

$$\frac{\partial s}{\partial a}=0,\qquad\frac{\partial s}{\partial b}=0$$

得到联立方程：

$$a\sum_{i=1}^{n}x_i^2+b\sum_{i=1}^{n}x_i=\sum_{i=1}^{n}x_iy_i$$

$$a\sum_{i=1}^{n}x_i+nb=\sum_{i=1}^{n}y_i$$

解出a、b。设xᵢ的平均值为x̄，yᵢ的平均值为ȳ，则：

$$a=\frac{\sum_{i=1}^{n}(x_i-\bar{x})(y_i-\bar{y})}{\sum_{i=1}^{n}(x_i-\bar{x})^2},\qquad b=\bar{y}-a\bar{x}$$

过程接收的实数数组xData、yData，元素个数均等于观测点数，分别保存xᵢ和yᵢ。

```text
○regressionEquation(
    实数型数组: xData,       // 保存观测值xᵢ
    实数型数组: yData,       // 保存观测值yᵢ
    整数型: n               // 观测点数
)
    实数型: sx ← 0, sy ← 0, sxx ← 0, sxy ← 0
    实数型: mx, my, a, b
    整数型: i
    for (i从1到n，每次增加1)
        sx ← sx＋xData[i]
        sy ← sy＋yData[i]
    endfor
    mx ← sx÷n
    my ← sy÷n
    for (i从1到n，每次增加1)
        sxx ← sxx＋(xData[i]－mx)×(xData[i]－mx)
        sxy ← sxy＋【a】
    endfor
    a ← 【b】
    b ← my－a×mx
    输出a和b的值
```

**答案：イ。**

本题用最小二乘法求回归方程y=ax＋b的系数。题干中的偏导数、带Σ的联立方程可能让人不清楚如何计算，但实际询问的是过程regressionEquation中的空白。该过程只需根据最终的系数公式求a、b。因此重点是思考这些公式需要哪些处理，再与程序对应。

> 脚注1：最小二乘法的概念见本节专栏。
>
> 脚注2：实际考试中，数理、数据科学、AI题材也常采用这种形式。不要被困难的术语和公式干扰，应找出解题所需部分，冷静作答。

a的分子是从i=1到n，累加(xᵢ−x̄)(yᵢ−ȳ)；分母是累加(xᵢ−x̄)²。xᵢ、yᵢ就是xData[i]、yData[i]，x̄、ȳ是这两个数组的平均值。因此，要先计算两数组的平均值。

平均值=全部元素之和÷元素个数。题目说明数组元素个数等于观测点数n，所以程序前半部分是在求平均值。

|变量|作用|
|---|---|
|sx|xData所有元素之和|
|sy|yData所有元素之和|
|mx|xData平均值x̄|
|my|yData平均值ȳ|

第一个for求总和，循环后除以n得到平均值。第二个for及其后面的语句求系数，关键是sxx、sxy的含义。

**空白a：**sxx累加(xData[i]−mx)²，对应系数a的分母。因此sxy应累加分子中的每一项，填：

```text
(xData[i]－mx)×(yData[i]－my)
```

**空白b：**分子已保存在sxy，分母在sxx，所以填`sxy÷sxx`。之后的`b ← my－a×mx`就是b=ȳ−ax̄。

### 专栏：最小二乘法很难吗？！

最小二乘法就是求y=ax＋b的a、b，使数据与直线之间的残差平方和最小。

例如散点图呈现“x增加时y也增加”的趋势，就假设最符合数据的直线为y=ax＋b，再用最小二乘法求其系数。

取任意观测点Pᵢ(xᵢ,yᵢ)，从它沿平行y轴的方向作直线，与回归直线交于Qᵢ(xᵢ,axᵢ＋b)。这里的残差是Pᵢ、Qᵢ的纵向差，即：

```text
εᵢ = yᵢ－(axᵢ＋b)
```

求使Σ[yᵢ−(axᵢ＋b)]²最小的a、b，就是最小二乘法。“最小二乘”即“平方和最小”的意思。

原书说明，考试不要求推导a、b公式，知道概念即可。不过下面两点可能考查，应掌握：

- x增大时y也增大，即正相关，回归系数a为正。
- x增大时y减小，即负相关，回归系数a为负。

图例为正相关，回归方程y=2x＋1。x=3时可以预测y=7。

**答案：イ。**

本题考查编码阶段对性能效率，尤其时间效率的考虑，即如何改善运行时间。

首先要找出原程序中时间效率低下的位置。应关注执行时间较长的sub：调用次数越少，时间效率越好。

原程序有两个位置调用sub(r)，分别在if条件与赋值中。r是外层for的控制变量，在内层循环期间并不改变。因此这两个位置都是完全相同的调用，返回值也相同，这就是低效之处。原程序最多调用rMax×cMax×2次。

> 脚注1：for控制变量用于控制循环次数，原则上不在循环体中另外修改。

其他选项：

- ア：仍在内层for调用，次数为rMax×cMax，相比原程序最多减少一半，并非最优。
- ウ：调用次数与ア相同，而且有错误。xrc只是保存x[r,c]值的普通变量，给xrc赋s1不会修改x[r,c]。
- エ：调用次数与イ相同，但与ウ一样，没有真正修改x[r,c]。

### 专栏：从时间效率看优化

提高时间效率的优化包括：

- 将始终不变的变量替换为常量。
- 将循环内部值不变的表达式移到循环外，本题即属于这种情况。
- 将幂运算改为乘法，将乘法改为加法等。例如将`3x³＋8x²＋5x＋2`变形为`((3x＋8)x＋5)x＋2`。

## 4.23　程序的测试用例（第232～235页）

### 例题

选择a、b的正确组合。

为了减少开发程序中遗漏缺陷的情况，着眼于程序的指令、路径、判断条件，创建满足测试计划中覆盖标准的测试用例及数据，确认程序行为。

覆盖标准包括：每条语句至少执行一次的语句覆盖；每个分支的所有出口路径至少执行一次的判定覆盖，以下也称分支覆盖。本题采用分支覆盖。

**判断条件的求值规则：**判断条件包括一个条件构成的简单条件，以及由两个或更多简单条件用and、or连接的复合条件。例如`(a>b) and (a<c)`，括号内是两个简单条件，整体是复合条件。

复合条件从左到右依次求值。一旦整体结果确定，就不再求值剩余条件。例如第一个条件a>b为假时，无论a<c真假，and整体都为假，因此不求值第二个条件。

下表是按分支覆盖创建的测试用例。按上述求值规则执行测试，用例①会出现【a】，用例②会出现【b】。

```text
○整数型: func(整数型:a, 整数型:b, 整数型:c, 整数型:d)
    整数型: n ← 0
    if ((a < 10) or (b < 20))
        n ← 10
    else
        n ← 20
    endif
    if ((c > 10) and (d > 10))
        n ← n＋1
    else
        n ← n－1
    endif
    return n
```

|测试用例|a|b|c|d|
|---|---:|---:|---:|---:|
|①|9|19|10|10|
|②|10|20|11|11|

|选项|a|b|
|---|---|---|
|ア|不求值b<20|不求值c>10|
|イ|不求值b<20和c>10|不求值d>10|
|ウ|不求值c>10和d>10|求值所有简单条件|
|エ|不求值b<20和d>10|求值所有简单条件|

### 解析

**答案：エ。**

本题问采用分支覆盖标准的测试用例，在求值时会得到什么结果。这里并非判断程序是否正常，而是确认所有简单条件是否都实际被求值。关键是题目指定的复合条件求值方式：从左到右，一旦结果确定，就跳过剩余部分。

> 脚注1：覆盖率表示测试确认了整体的多少，是衡量测试范围的指标。

**测试用例①：a=9、b=19、c=10、d=10。**

**测试用例②：a=10、b=20、c=11、d=11。**

因此①跳过b<20和d>10，②会对所有简单条件求值。

### 专栏：判定覆盖（分支覆盖）

分支覆盖要求每个分支的所有出口路径至少执行一次，也就是每个判断条件的真、假两种结果都至少测试一次。

本题两个用例合起来，确实测试了所有判断条件的真、假两个分支。但用例①仍有未求值的简单条件。这样就可能无法发现简单条件本身的错误。

为解决这一问题，可以结合**判定覆盖与条件覆盖**。条件覆盖要求构成判断的每个简单条件，都测试真、假两种结果。结合使用，就能同时覆盖整体判断的真假以及各简单条件的真假。

### 专栏：利用期望值原则进行决策

当能够预测未来可能状态及发生概率时，可以使用期望值原则作为决策标准。

### 专栏：原始蒙特卡罗法

```text
整数型数组: array ← {1,2,3,4,5}
整数型: right, left
整数型: tmp

// left、right 是数组下标，表示要交换的两个位置。
// tmp 是临时变量，用来保管即将被覆盖的值。
// 本题下标从 1 开始，所以 5 个元素的位置是 1、2、3、4、5。

for (left从1到array元素个数÷2的整数商，每次增加1)
    // 5 ÷ 2 的整数商是 2，所以 left 只取 1 和 2。
    // 每轮交换一对位置。第 3 格在正中间，不用交换。

    right ← array元素个数 − left ＋ 1
    // 空格 a：算出与 left 对称的右边位置。
    // left = 1 时，right = 5 − 1 ＋ 1 = 5。
    // left = 2 时，right = 5 − 2 ＋ 1 = 4。
    // 如果漏掉 ＋1，第一轮就会错误地交换第 1 格和第 4 格。

    tmp ← array[right]
    // 先把右边原来的值保存起来。
    // 第一轮：把第 5 格原来的 5 存进 tmp。

    array[right] ← array[left]
    // 把左边的值写到右边。
    // 第一轮：把第 1 格的 1 写到第 5 格。
    // 此时数组暂时是 {1,2,3,4,1}，原来的 5 还保存在 tmp 里。

    array[left] ← tmp
    // 空格 b：把右边原来的值写到左边，完成交换。
    // 第一轮：把 tmp 里的 5 写到第 1 格，得到 {5,2,3,4,1}。
    // 如果写成 array[right] ← tmp，就会把右边恢复原样，根本没有交换。
endfor

// 第一轮：交换第 1、5 格 → {5,2,3,4,1}
// 第二轮：交换第 2、4 格 → {5,4,3,2,1}

// 记法：下标从 1 开始时，对称位置满足 left + right = 元素个数 + 1。
// 交换顺序：先存右边 → 左边写到右边 → 把存好的值写到左边。
// 答案：ウ
// a = array元素个数 − left ＋ 1
// b = array[left]
```

```text
// 链表为空时，没有第一个节点，所以 listHead 是未定义。

    ListElement: prev, curr
    // curr：指向新建的节点。
    // prev：从链表开头一路往后找，最后指向原来的尾节点。
```

### 第13题　答案：ウ（第294～295页）

本题考查二分查找。search本想用二分查找寻找target，但由于缺陷，某些情况下会无限循环。无限循环指重复处理永远持续，程序不能结束。本函数中，若始终无法让low≤high变为假，即low不能超过high，而且没有找到值返回，就可能陷入无限循环。

|变量|作用|
|---|---|
|low|查找范围左端下标|
|high|查找范围右端下标|
|middle|查找范围中间位置下标|

逐项检查：

- ア：例如data={3}、target=3。low=high=1，middle=1，正好相等，执行return middle结束。
- イ：例如data={3,8}、target=3。low=1、high=2，middle是(1＋2)÷2的整数商1，正好相等，返回1结束。
- ウ：data={3,8}、target=8。middle=1，data[1]<8，执行low←middle，但middle仍为1，low根本没有变化。下一轮所有数值与前一轮相同，永远无法使low>high，形成无限循环。
- エ：包含−1本身并不一定导致问题。例如data={−1}、target=−1，和ア相同，可以直接找到并结束。

所以答案为ウ。

> 脚注10：二分查找概要参见第2章“二分查找的问题”（第60页）。

#### 专栏：有缺陷的二分查找程序

原程序更新low、high的方法有问题。查找值不存在时，某个时刻low或high不再改变，导致无限循环。查找值等于末元素时也会出现本题的情况；等于首元素时则不会。选项特意限定“只有两个元素”，是为了降低理解难度。

若middle改为将(low＋high)÷2向上取整，则情况会反过来：查找首元素会无限循环，查找末元素不会。

正确修正方式是排除已经比较过的middle：

```text
low ← 1
high ← data的元素个数
while (low ≤ high)
    middle ← (low＋high)÷2的整数商
    if (data[middle] < target)
        low ← middle＋1
    elseif (data[middle] > target)
        high ← middle－1
    else
        return middle
    endif
endwhile
return −1
```

请用修正后的程序检查选项ウ，可以确认不再无限循环。

### 第15题　答案：ア（第297页）

本题考查博弈树。按题干步骤3，从最下层评估值向上一层层计算：轮到自己取子节点最大值，轮到对手取最小值。

A分支：对手可以在中下落×，随后自己只能在右下落○，结果平局0；也可以在右下落×，随后自己在中下落○获胜10。自己回合的两个中间节点分别评估为0、10；A节点是对手回合，取min(0,10)=0。

B分支：对手可以在左下落×直接获胜，自己评估为−10；或在中下落×，随后自己落左下○形成平局0。因此B节点取min(−10,0)=−10。

所以a=0，b=−10。

> 脚注11：博弈树参见“4.25 博弈树搜索”（第240页）。

### 第16题　答案：ク（第298～300页）

encode将Unicode字符转为UTF-8。Unicode字符有称为码点的整数值，本题处理800(16)～FFFF(16)，使用3字节编码。例如“あ”的码点3042(16)，其二进制为11000001000010，右对齐填入模板`1110xxxx 10xxxxxx 10xxxxxx`，未填位置补0，得到`11100011 10000001 10000010`。

utf8Bytes初始为{224,128,128}，对应模板中x全部置0后的值：

|下标|十进制|二进制|
|---:|---:|---|
|1|224|11100000|
|2|128|10000000|
|3|128|10000000|

因此，程序实际上根据cp的位，填入各元素的低位0。for的i从3递减到1，依次进行：

1. utf8Bytes[3]低6位填入cp第1～6位。
2. utf8Bytes[2]低6位填入cp第7～12位。
3. utf8Bytes[1]低4位填入cp第13～16位。

> 脚注12：十六进制每位对应4个二进制位。3042(16)逐位转换为0011、0000、0100、0010。
>
> 脚注13：注意循环每次是减1。
>
> 脚注14：这里位编号从右端开始，依次为1、2、3……。

为什么最后说第13～16位，而不是只考虑“あ”的14位？因为cp是整数类型，内部按固定宽度保存。3042(16)可表示为16位`0011000001000010`，高2位为0。因此将第13～16位的4位填入首字节低4位即可，不必单独处理“剩余x补0”。

循环通过加上cp除以某数的余数，填入相应低位。关键在于，给初值128（二进制10000000）加上0～63，即6位值，不会改变高2位：

```text
128＋1  = 10000000＋00000001 = 10000001
128＋2  = 10000000＋00000010 = 10000010
……
128＋62 = 10000000＋00111110 = 10111110
128＋63 = 10000000＋00111111 = 10111111
```

因此，第1轮只需把cp低6位表示的数加到utf8Bytes[3]。取得低6位的方法就是求cp除以2⁶=64的余数。除以2⁶取整数商，相当于右移6位，被移出右端的位就是余数。

所以空白填64。每处理一个字节，再执行cp←cp÷64的整数商，就让原第7位移到最低位，下一轮能够使用相同处理。

填完后的循环：

```text
for (i从utf8Bytes的元素个数到1，每次减少1)
    utf8Bytes[i] ← utf8Bytes[i]＋(cp除以64的余数)
    cp ← cp除以64的整数商
endfor
```

**以“あ”为例跟踪：**cp最初为`0011000001000010`。

|轮次|i|处理前cp（二进制）|除以64的余数|本轮计算|除以64后的cp|
|---:|---:|---|---|---|---|
|1|3|0011000001000010|000010|10000000＋000010=10000010|0000000011000001|
|2|2|0000000011000001|000001|10000000＋000001=10000001|0000000000000011|
|3|1|0000000000000011|000011|11100000＋000011=11100011|0000000000000000|

最后utf8Bytes为：

```text
{11100011,10000001,10000010}
```

即十进制{227,129,130}。

> 脚注15：原书将utf8Bytes的整数元素也视为2字节，因为同为整数类型的cp需要保存800(16)～FFFF(16)，至少需要2字节。因此图中实际只画低8位，各元素前面的8位均为0。
>
> 脚注16：处理首字节时，cp除以64所得余数的高2位必为0，因此加到utf8Bytes[1]也不会影响其高4位前缀。
